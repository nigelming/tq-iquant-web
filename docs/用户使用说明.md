# 创懿量化交易平台 — 使用说明

> 版本：封装版（`main/dist/tq-iquant`）／源码版（前端 `web/`，后端 `main/`，Python 3.13 + Vue 3 + FastAPI）

## 一、首次启动

**封装版（推荐给不使用 TQ 修改开发的用户）**

1. 双击分发目录（`main/dist/tq-iquant`）下的 `启动.bat`。
2. 首次启动会自动创建 `data/`（SQLite 数据库）并执行数据库迁移（Alembic，16 个迁移），并自动打开浏览器 `http://127.0.0.1:8888`。
3. 停止：关闭浏览器即可；程序为后台进程，如需真正退出，在任务管理器结束 `tq-iquant.exe`。已运行时会先检查 8888 端口，重复双击只会重新打开浏览器。

**源码版（开发模式）**

```bash
# 后端（main 目录）
uv run uvicorn core.main:app --reload        # http://127.0.0.1:8000

# 前端（web 目录，另开终端）
npm install
npm run dev                                    # Vite dev server，/api 代理到 8000
```

前置依赖：通达信客户端（行情/日线数据来源，见「系统配置」）、国信 iQuant 客户端（实盘桥，仅实盘需要）。

## 四、股票池

> 通达信规范股票代码统一带后缀：`000001.SZ` / `600000.SH` / `002415.SZ`。

- **左侧「通达信库」**：读取通达信客户端已存在的股票池列表；可查看池内股票。
- **右侧「本地库」**：导入回的池子（含同步来源代码映射）。
- 操作按钮（按状态显示）：
  - `查看` — 展开池内股票列表（仅在通达信端存在时显示）。
  - `同步` — 将通达信端最新池内容同步到本地（两端始终显示同一文案；本地列表加载失败不阻塞通达信列表）。
  - `删除` — 在本地删除该池（依赖本地映射，删除后再导入会新建）。
- 用途：回测时组合策略选择某一股票池，作为选股范围。

## 五、公式管理

> 公式 = 通达信技术指标公式。平台在**回测引擎内嵌入通达信 TQ 模块直接调用公式计算**，因此信号与客户端一致。

- **列表**：从通达信加载可用公式；`user_only=true` 可过滤只看用户公式。
- **导入**：把选择的通达信公式（get/read 类，含所需输出）导入平台，供组合策略子策略使用。
- 支持按 `ac_code`/`公式类型` 查看公式详情（`GET /formulas/tdx-info`）。
- 导入后在「组合策略」的策略公式字段中直接引用 `公式名`，配合买入/卖出/加减仓信号名使用。

**✳ 公式信号取值契约（务必遵守）**

平台判定信号是**精确相等匹配**：`公式输出值 == 配置的触发值(trigger_value)`，相等才触发，不按阈值区间判断。

1. 公式必须有与「信号名」**同名**的输出行（如输出 `买入` / `卖出` / `加仓` / `减仓`，名字随意，但必须与配置中的 `signal_name` 完全一致）。
2. **买卖取值约定**：买入输出 `1` 或 `2`；卖出输出 `-1` 或 `-2`。`0` 表示「未触发」的常态值，平台**禁止**将其配置为触发值。
3. `trigger_value` 仅允许 `{-2, -1, 1, 2}`，配置/导入时平台校验，其他值返回 HTTP 400（见 `core/api/formulas.py` `VALID_TRIGGER_VALUES`）。
4. 每个信号对应一行配置（信号名 + 信号类型 + 触发值），同一公式可含多个信号输出。典型配对：

| 信号类型 | 含义 | 触发值 |
|---|---|---|
| `OPEN` | 开仓 | 1（或 2） |
| `ADD` | 加仓 | 2（或 1） |
| `REDUCE` | 减仓 | -2（或 -1） |
| `CLOSE` | 清仓 | -1（或 -2） |

5. 提交回测时平台会校验：信号名必须在所选公式输出中**存在**、且触发值与配置一致，否则拒绝该回测（报错提示「信号不存在」/「触发值不匹配」）。

## 六、组合策略

> 组合策略 = **一个组合（Portfolio）** + 组合下的**多个子策略（Strategy）**。组合定全局资金/费用/熔断参数；子策略定选股公式、周期、资金占用与个票风控/加仓。资金按「持仓上限」分配（非预分），多策略上限之和可超 100%。

### 组合（Portfolio）参数

| 字段 | 说明 | 默认 |
|---|---|---|
| 名称 | 组合名称（非空） | — |
| 股票池 | 组合级选股池（**必选**）；子策略未设独立池时继承它 | — |
| 基准指数 | 绩效对比基准（通达信代码） | `000300.SH` |
| 初始资金 | 回测/实盘模拟起始资金（元） | 500,000 |
| 最大回撤 | 全局回撤熔断线 (0,1)：回撤超过 → 暂停新开仓，次日恢复；**累计触发 3 次后转手动恢复** | 20% |
| 日亏损限额 | 当日亏损限额 (0,1)：当日超过 → **当日暂停**新开仓，次日恢复 | 5% |
| 持仓上限 | 组合最大同时持仓数 | 10 |
| 最低佣金 | 单笔最低佣金（元，不足按此收取） | 5 元 |
| 买佣金率 | 买入佣金费率 | 0.025% |
| 卖佣金率 | 卖出佣金费率 | 0.025% |
| 印花税率 | 卖出时征收 | 0.05% |
| 滑点 | 成交滑点（按成交价比例） | 0 |
| 交易时段 | `full` 全时段 / `am` 仅上午 / `pm` 仅下午 | full |
| 状态 | `active` 启用 / `archived` 归档 | active |

约束：`max_drawdown`、`daily_loss_limit` 必须在 `(0,1)`；被回测/实盘记录引用的组合、子策略不可删除（返回 409/400）。

### 子策略（Strategy）参数

> 子策略引用**一个已导入的公式**，买卖信号 = 该公式上配置的全部信号（signal_name + signal_type + trigger_value，见「五、公式管理」信号契约）。

| 字段 | 说明 | 默认 |
|---|---|---|
| 名称 | 子策略名称（非空） | — |
| 公式 | 必选；信号来自该公式 | — |
| 周期 period | `1m / 5m / 15m / 30m / 1h / 1d / 1w / 1mon`（注意**没有 60m**，两端不认） | — |
| 角色 role | `independent` 独立 / `master` 主 / `slave` 从 | — |
| 主策略 | 仅 `slave` 必填，指向**同组合**下 `master`（不可指向自身） | 无 |
| 从策略退出模式 | `independent` 自身信号/风控卖出 / `follow_master` 主策略卖出某股时从策略强制同步卖出该股（仅 slave 有效） | independent |
| 策略股票池 | 空 = 继承组合级；非空 = 本策略独立池。**slave 池必须 ⊆ 主策略池**，否则直接拒绝或该股永不成交 | 继承组合级 |
| 资金占比 | (0,1]：该策略占总资金上限（非预分，各策略之和可超 100%） | 60% |
| 持仓上限 | 该策略最大同时持仓数 | 5 |
| 单笔占用 | 单次开仓占总资金比例 | 10% |
| 止损 | 现价较**成本价**下跌 ≥ 该比例 → 清仓 | 5% |
| 止盈 | 现价较**成本价**上涨 ≥ 该比例 → 清仓 | 15% |
| 移动止损 | 现价较**持仓期最高价**回撤 ≥ 该比例 → 清仓（股价创新高后峰值自动上移） | 3% |
| 加仓阈值 | `-1`＝任何价格有 ADD 即加（含上涨/大涨）；`0`＝不涨即加（现价≥成本）；正常值＝现价较成本**下跌 ≥ 阈值**才加 | 5% |
| 加仓次数 | `[0,10]`，`0`＝禁加仓 | 2 |
| 加仓比例 | 每次加仓买入量占总资金比例 | 10% |
| 减仓比例 | 减仓（REDUCE）时卖出持仓比例 | 30% |

**信号执行优先级（总序）**：风控信号（止损 > 止盈 > 移动止损，触发任一即先出场）**高于**公式信号（OPEN 开仓 / ADD 加仓 / REDUCE 减仓 / CLOSE 清仓）。例：已涨到止盈点 → 先止盈清仓，同一 bar 不再执行 ADD。回测强制 **T+1**（当日买入次日才可卖）。

### 主从策略规则（易错）

- `slave` 只能买入 `master` **当前持有**的同一只股票（slave 池 ⊆ master 池，越界股永久无法成交）。
- `master` 清仓某股后：`slave` 不可再新开该股，但**存量可自行卖出**。
- `follow_master` 模式：`master` 卖出某股时，`slave` 若持有该股强制同步卖出。

### 配置校验速查（不满足直接 400）

- 角色/周期/交易时段/状态走白名单；`capital_ratio ∈ (0,1]`；加仓阈值须为 `-1` 或 `[0,1]`；加仓次数 `[0,10]`。
- `slave` 必须指定同组合下的 `master`（角色必须为 master，不能指向自己）。
- slave 池 ⊆ master 池（组合改股票池后会重校全部主从对）。

## 七、回测管理

### 7.0 启动回测前的准备（务必先满足，否则回测失败或零交易）

一条「今天可跑」的回测依赖下面全部成立：

1. **通达信** 已启动、可读历史数据（行情/日线/周线来源；`tdx_path` 指向其安装目录）。
2. **股票池**：组合绑定的股票池**已有成分股**（需先在通达信端存在，必要时先「同步」）。池空 → 无票可买，回测零交易。
3. **公式**：已导入通达信公式且**配置了信号**（trigger_value ∈ `{-2,-1,1,2}`），公式输出中确有与 `signal_name` 同名的输出线。
4. **组合策略**：组合非空、绑定股票池、含**至少一个子策略**；子策略 `period` 应与公式主图周期一致（"30 分钟公式挂到日线策略"是典型零信号坑）。
5. **区间**：`start_date < end_date`，且 `start_date` 不晚于今天。

平台提交回测时会做**信号预检**（非阻塞但务必看警告）：公式执行失败 / 信号输出线在公式中不存在 / 信号在区间内从未等于触发值 → 按警告修正后再跑，避免跑完才发现零交易。

### 7.1 发起回测

表单字段：

| 字段 | 说明 |
|---|---|
| 组合策略 | 选择一个组合策略（含其全部子策略与股票池） |
| 回测名称 | 记录名称 |
| 起止日期 | 开始 < 结束，且开始不晚于今天（TQ 拉不到未来数据） |
| 复权模式 | `front` 前复权（默认）／`back` 后复权／`dual` 前复权信号+后复权记账（**推荐**，模拟实盘口径） |

规则要点：
- 同一时刻最多 `max_concurrent_backtest`（默认 1）个回测运行，并发启动返回 HTTP 409；成功后前端轮询记录状态。
- 引擎：事件驱动（polars 核心），内嵌通达信 TQ 实时计算公式信号；**T+1 强约束**（当日买入次日才可卖）；成交按 `next_bar.open` 模拟并扣减组合费用参数（佣金/印花税/滑点）。
- 复权模式：长区间前复权有「加性压缩」导致历史价逼近 0/负的问题（假收益）；`dual`（前复权信号 + 后复权记账）规避假收益，**推荐**。
- 回测**仅支持单组合策略**（多组合联动只在实盘体现）。

### 7.2 回测记录列表

每条记录展示：ID、名称、组合策略、起止日期、状态（运行中/已完成）、操作（`查看` / `删除`，删除为级联删除，含详情/分析数据）。

### 7.3 回测详情分析（在线）

详情页是**多维分析 + 图表**，各区块：

- **关键指标摘要**：总收益/年化/最大回撤/夏普等。
- **综合评估指标**：18 项评估指标（基于每日快照计算）。
- **净值曲线 / 回撤曲线**：与基准对比。
- **策略绩效评估**：组合整体 + 各子策略指标（收益、回撤、夏普、交易数等）。
- **收益分布**：月度收益热力图、年度日收益箱线图、年度月收益箱线图、各年年收益柱状图。
- **🔬 危机Alpha（折叠）**：十二模块完整防守评估 —— 核心结论 / 产品与基准走势 / 历届危机Alpha防守要点 / 极端下跌周 TOP / 全周期四象限分类 / 自然回撤事件清单 / 多宽基一致性 / 月度视角 / 动态相关性 / 代价检验（平均表现）/ 综合危机保护评分 / 全部下跌周明细。
- **市场状态（折叠）**：市场状态与超额收益 / 行业归因（结构对比） / 市场拥挤度（相对基准）/ 下跌周归因淋雨图 / 行业贡献分解 / 稳健性检验等。
- **🔬 稳健性检验（折叠）**：年度收益与最大回撤 / 三年滚动（CAGR + 最大回撤） / 累计交易实现 P&L 集中度 / 样本内·样本外对比（默认 75/25 自动切分）。提供 `重新计算` 按钮。
- **换池稳健性对比**：选择**其他股票池**（同参数仅换池）逐个重跑回测并对比（年化/最大回撤/夏普/胜率/盈亏比/交易数/仓位利用/基准/样本外 CAGR）。界面提供「推荐池」快捷选择（成长精选 / 红利精选 / 热点精选）。
- **风控与拦截统计**：按闸门聚合（触发次数/涉及股票数/时间范围），点某闸门可下钻逐条事件明细（时间/策略/代码/阈值/实际值/原因）。
- **交易明细**：全部成交记录（时间/策略/代码/买卖/价格/数量/金额/佣金/印花税）。
- **导出报告**：`导出 HTML 报告` —— 生成**单文件离线报告**（内联 ECharts 与全部图表/数据，无外链），双份内容可下载保存 / 打印 / 分享。

### 7.4 离线 HTML 报告（导出）

- 单文件 `.html`，浏览器打开即可离线查看，内容与在线详情**数据同源**（不重跑、不新增口径）。
- 包含：绩效评估、收益分布、危机Alpha、市场状态、稳健性检验、风控统计、交易明细等全部区块。
- 文件名为 `回测报告-<记录名>.html`（UTF-8 文件名，直接下载）。

## 八、实盘交易

> 架构：Core（Python 3.13）↔ iQuant 桥策略（国信 iQuant 客户端内 Python 3.6）通过 HTTP 桥（`127.0.0.1:8790` 仿真 / `8791` 实盘）通信；行情/下单均走桥。未配置桥或 iQuant 未运行时实盘不可用。

### 8.1 会话管理

- **新建会话**：会话名称 + 交易模式（`仿真 simulation` / `实盘 live`）+ 组合策略（支持**多组合多选**，共享同一 iQuant 账户，各组合独立维护虚拟持仓与虚拟现金）。
- **启动 / 停止**：启动后进入轮询（行情/订单/账户），实时事件经 **SSE**（`/api/live/sessions/{id}/stream`）推送前端，非轮询。
- **删除**：删除会话记录。
- 会话列表展示：ID、名称、模式、关联组合（`active` / `circuit_broken` 状态徽章）、操作。

### 8.2 实时事件日志（SSE）

顶部事件面板实时流转以下事件类型（带颜色标识）：

`signal 信号` / `order 委托` / `trade 成交` / `position 持仓` / `risk 风控` / `decision 决策拦截`（心跳 `ping` 不进日志）。日志上限 200 条滚动。

### 8.3 工作台（按会话）

- **持仓**：实时持仓 u点（虚拟持仓，多组合独立）。
- **委托**：委托状态 `已提交/全部成交/部分成交/已拒绝/已撤单`。
- **成交**：成交明细（含 T+1 可用股数实时校验）。
- **决策/拦截**：逐条决策事件 + 聚合统计（按闸门：止损/止盈/移动止损/公式信号/熔断……）；拦截数量显示「请求 → 实际（全拦→0/缩减→N）」。

### 8.4 熔断恢复

组合触发 `max_drawdown`（累计 3 次）或 `daily_loss_limit` 熔断后状态为 `circuit_broken`，该组合暂停开仓（不清仓）。可点击 **恢复** 手动清零熔断计数并恢复开仓（会弹确认框）。

> 实盘收入规则：信号优先级 = 风控 > 公式；多周期可同时触发（一个 5m bar 同时命中多个周期）；T+1 实时查询可用股。

## 十、关键业务规则一页纸

- **股票代码**：统一带后缀（`000001.SZ` 等，通达信规范）。
- **信号优先级**：风控（止损/止盈/移动止损）> 公式信号（OPEN/ADD/REDUCE/CLOSE）。
- **加仓阈值特殊值**：`-1` = 跳过回撤检查只要有 ADD 即加（含上涨/大涨）；`0` = 不涨即加；正常 1%~20% 逢跌加仓。`max_add_count` 次数上限仍生效，风控优先级仍高于 ADD（到止盈点先止盈不加）。
- **资金模型**：策略资金占比是持仓上限（非预分），多策略之和可超 100%。
- **T+1 约束**：回测强制 T+1；实盘实时查可用股数。
- **熔断**：`max_drawdown` → 次日恢复（累计 3 次后转手动恢复）；`daily_loss_limit` → 当日暂停，次日恢复。熔断仅暂停新开仓，不清仓。
- **主从策略**：从策略只能买主策略当前持有的同一只股票；主策略清仓后从策略不可新开仓但存量可自行卖出。
- **多周期同时触发**：一个 5m bar 可能同时触发多周期公式（5m+30m+60m）。
- **多组合实盘**：一个会话可含多组合，共享账户下单，各自独立虚拟持仓/现金；Core 重启时从成交记录聚合重算虚拟持仓与现金。
- **回测仅单组合**：多组合行为只在实盘体现。
- **基准口径**：绩效对比基准 = 组合绑定的基准指数，按同期行情归一。

## 十二、常见问题

**Q0：能否把打包目录拷到别的电脑直接运行（无 Python 环境）？**
可以。`main/dist/tq-iquant` 为 Nuitka 独立打包，解释器 + 全部依赖均随包，目标机无需安装 Python。要求：
1. **Windows x64** 电脑，且已安装**通达信 TQ 客户端**（行情/历史数据来源）。
2. 拷贝**整个 `tq-iquant` 文件夹**（不要只拷 exe，依赖在 `_internal\` 等子目录）。
3. **修改通达信路径**：包内 `config.yaml` 的 `tdx_path` 默认是构建机路径（如 `D:\zd_zyb`），需改成目标机通达信安装目录——可启动前直接编辑该文件，或启动后在「系统配置 → 通达信目录」设置并保存（配置随 exe 同级目录读写，可移植）。
4. 首次启动自动创建 SQLite 数据库并执行全部 Alembic 迁移，无需手动建库。
5. 仅实盘需要额外安装国信 iQuant 客户端并配置桥地址；纯回测不需要。
6. 若杀毒软件拦截 exe，添加信任后再启动。

**Q1：双击启动.bat 提示"等待30秒后服务仍未就绪"**
1. 检查 8888 端口是否被占用（`netstat -ano | findstr 8888`），关闭占用的程序。
2. 杀毒/安全软件是否拦截 exe，添加信任。
3. 保持整个目录完整，不要单独移动 exe（依赖 `_internal/`）。

**Q2：回测发起失败"/ 复权模式仅支持 front/back"**
说明运行的是旧版后端。封装版请重新打包或确认使用最新 exe；源码版请重启 uvicorn（旧进程不会热加载已提交代码）。

**Q3：离线报告导出 500**
确认包装含 `echarts.min.js`（`main/dist/tq-iquant/echarts.min.js`，1.1MB）。源码版需 `web/node_modules/echarts/dist/echarts.min.js` 存在。

**Q4：实盘看不到行情/无法下单**
确认 iQuant 客户端已登录、桥策略已启动（8790/8791），并在「系统配置」填写桥地址；仿真模式走仿真桥，实盘模式走实盘桥。

**Q5：如何让封装版使用最新数据**
封装包自带独立 `data/`（构造时保留旧包数据）。如需同步源码版数据库，停止 exe 后将源码 `main/data/dev.db` 覆盖到 `main/dist/tq-iquant/data/dev.db`（并删除残留的 `dev.db-wal`/`dev.db-shm`）后重启。

**Q6：开发模式改了后端不生效**
uvicorn 若未带 `--reload` 或 reload 失效，重启 `uv run uvicorn core.main:app --reload` 后再试。
