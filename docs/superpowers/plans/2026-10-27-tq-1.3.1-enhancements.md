# TQ 1.3.1 七项增强批次 — 实施计划

> 来源：`docs/2026-10-27-tqcenter-1.3.1-audit.md` 审计结论，用户选定 7 项一次批次实施。
> 执行起点前先将本文件转存 `docs/superpowers/plans/2026-10-27-tq-1.3.1-enhancements.md` 并提交。

**Goal:** 创懿平台 TQ 集成层接入 1.3.1 新增能力：formula_by_src 试算、权威交易日历、行情退订、
真实涨跌停校验、自选股写入、批量行情轮询、除权除息查询。

**Architecture:** 包装层（core/tq）薄封装 1.3.1 API → TdxTqDispatcher/BarPoller 消费（能力探测+回退）→
REST API → 前端三处入口。全部 TQ 调用走 `get_tdx_lock` + stdout 重定向（`_call` 模式）；
日历/涨跌停/退订失败一律 fail-open 不阻断主流程。

**Tech Stack:** Python 3.13 / FastAPI / pytest（fake-tq 注入，参照 test_tdx_tq_dispatcher.py）；
Vue3 + vitest。测试不依赖真实通达信。

### Task 2: dispatcher 与引擎层

**Files:** Modify `main/core/engine/tdx_tq_dispatcher.py`、`main/core/engine/bar_poller.py`、
`main/core/engine/live_engine.py`；Test `test_tdx_tq_dispatcher.py`、`test_bar_poller*.py` 增补

- `query_calendar` 重写：优先 `TQData.get_trading_dates`（近 600 个交易日）→ 空则回退现有
  000001.SH 日线反推 → 再空返回 `[]`（calendar.py fail-open 契约不变，元素 'YYYYMMDD'）。
  alert/qmt/ths 均委托本方法，一处修改全受益。
- `close()`：调 `TQData.get_subscribe_hq_stock_list()` 记录当前订阅（对账日志）；对本会话
  股票池内已订阅的股票 `unsubscribe_bars`（全局限 1 运行 session，不会误伤）。`LiveEngine.stop()`
  末尾补 `self._dispatcher.close()`。
- `place_order` 涨跌停校验：`_ensure()` 后、`order_stock` 前调 `get_zdt_data([symbol])`
  （Value 字段名实现时探针实测后写候选键表）；限价买 `price >= 涨停价` /
  限价卖 `price <= 跌停价` → `BridgeOrderRejected`（中文原因含阈值）；市价单
  （price<=0）与任何查询异常 fail-open 跳过。
- `query_quotes_batch(codes, period, count) -> Dict[str, list]`：一次
  `get_history_raw(stocks=codes, periods=[period])` 转 bars（同 `query_quote` 规则）；
  类属性 `supports_batch_quote = True`。仅 TdxTqDispatcher 有此属性。
- `BarPoller.poll()`：dispatcher 具备 `supports_batch_quote` → 一次批量取全部 stock_codes，
  分发行为与逐只完全一致；否则逐只回退（iQuant/ths/qmt 不受影响）。
  范围控制：market_data.py 增量/注入路径本次不动。
