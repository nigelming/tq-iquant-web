# 封装与授权方案

> 日期：2026-11-07
> 范围：任务一 = 对 `D:\通达信量化看板` 的封装实现做逆向核查（只读）；任务二 = 为「创懿私募基金量化平台」设计封装 + 授权方案。
> 本轮**未修改本项目任何代码/配置、未新增依赖、未执行对方安装程序、未改动 `D:\通达信量化看板` 下任何文件**。

## 0. 结论摘要

| 问题 | 结论 |
|---|---|
| 对方安装包是什么壳 | **NSIS 3.13（Unicode，`requireAdministrator`）**，`Nullsoft.NSIS.exehead` 清单 + `NullsoftInst` 魔术字为证；**不是** Inno Setup，也不是 MSI |
| Python 部分怎么打 | **Nuitka `--standalone`**（非 onefile、非 PyInstaller）。证据：`__compiled__` 常量、`python314.dll` + 平铺 `.pyd`、**PE 尾部 overlay=0**、**无 `_MEI` 魔术字 / 无 `base_library.zip` / 无 `PYZ-00`** |
| 前端怎么放 | **外置 `static/` 目录**（Vite 构建产物原样放在安装根），FastAPI `StaticFiles` + SPA 回退托管；桌面壳用 **pywebview + pythonnet + WebView2** |
| 怎么找通达信 | **不读注册表**：优先级「用户配置 > 环境变量 `TDX_HOME` > 默认 `D:\new_tdx64`」，并**磁盘目录扫描**候选名（`new_tdx64/new_tdx32/TdxW/通达信/...`）+ 探测 `PYPlugins\TPythClient.dll` |
| 「最新版本适配」改了什么 | 改用新版**64 位**通达信客户端 `PYPlugins\TPythClient.dll` 的 **TQ 通用接口**（`InitConnect` / `GetTdxDataStr` / `CloseConnect`），要求 **2026-09 之后**客户端；老接口（导出缺失）明确报错拒绝 |
| 有没有授权/代码保护 | **完全没有授权机制**（`机器码/激活/授权/许可证/到期` 字符串命中 0），也**没有 PyArmor/加壳**；唯一保护是 **Nuitka 编译本身**。两者均**未数字签名** |
| 本项目推荐封装 | **沿用现有 Nuitka standalone（`main/build_package.py`）**，补一个安装器（NSIS 或 Inno）+ 前端/数据外置；**不引入 onefile**，**不把桥脚本打进包** |
| 授权性价比最高 | **机器码 + 离线 Ed25519 许可证（含到期日/功能位）** 一层就够，成本约 1~2 天；在线激活只在「按年续费、需要吊销」时才值得 |
| 唯一必须接受的事实 | 纯 Python 本地程序**不可能绝对防破解**。我们这次能在 20 分钟内把对方 Nuitka 包里的中文注释、模块名、默认路径全 dump 出来，就是最直观的反例 |

## 任务一：`D:\通达信量化看板` 封装实现核查

### 1.1 核查对象与方法

| 对象 | 大小 | 时间戳 |
|---|---|---|
| `通达信量化看板-v0.2.0-setup(通达信最新版本适配).exe` | 43,802,155 B | 2026-11-07 23:06 |
| `通达信量化看板-v0.2.0.exe`（主程序） | 161,641,984 B | 2026-11-07 14:10 |
| `uninstall.exe` | 104,198 B | 2026-11-07 23:12 |

方法（全部只读，命令见附录 A）：

1. `Get-Item.VersionInfo` 读 PE 版本资源；`Get-AuthenticodeSignature` 验签；
2. 二进制转 Latin-1 / UTF-8 / UTF-16 字符串检索（等价于 `strings`），提取上下文；
3. 手工解析 PE 头（`e_lfanew` → COFF → 节表），计算**节表尾部 vs 文件大小**得到 overlay；
4. 检索 PyInstaller onefile 的 `MEI\x0c\x0b\x0a\x0b\x0e` 魔术字；
5. 读安装目录布局、`app/plugins/*.yaml`、`static/index.html`、`runtime_deps.json`、`VERSION`；
6. 查 `HKLM/HKCU\...\Uninstall` 注册表项。

> 局限：NSIS 的脚本与文件清单在 **LZMA 压缩块**里，本机没有 7-Zip 且未允许安装工具，故**没有做 payload 文件清单解包**；安装内容以「安装后的目录 + 注册表 + NSIS 头」为准，足以回答本次问题。

### 1.2 安装包外壳：NSIS 3.13

证据（`setup.exe` 内 ASCII 串）：

```text
<assemblyIdentity ... name="Nullsoft.NSIS.exehead" type="win32"/>
<description>Nullsoft Install System v3.13</description>
... requestedExecutionLevel level="requireAdministrator" uiAccess="false" ...
偏移 102,920: "NullsoftInst"（NSIS 数据块起始魔术字）
```

- `Inno Setup` / `InnoSetup` 命中 **0**；`Nullsoft` 命中 3，`NSIS` 命中 1。
- 另有一处 NSIS 独有的运行时文案（UTF-16 串区检索命中）：`verifying installer: %d%%` / `Installer integrity check has failed. Common causes include ...` / `Error launching installer` —— 这是 NSIS 的 CRC 自校验提示，进一步确认壳类型。
- NSIS 脚本正文与文件清单被压进 LZMA 数据块，明文检索不到安装路径/文件列表（这也是**没有做 payload 清单解包**的直接原因）。
- 安装器**要求管理员**（`requireAdministrator`），因此默认安装到机器级位置；实际装到 `D:\通达信量化看板`（用户选的路径）。
- 对比参照：同机另一个产品「看海量化回测平台」的卸载串是 `D:\khQuant\unins000.exe`——那是典型 **Inno Setup** 的命名；本产品是 `uninstall.exe` + `NullsoftInst`，属 NSIS 自定义卸载器名。
- `setup.exe` 与 `uninstall.exe` 均 **NotSigned**（无数字签名）。`uninstall.exe` 内同样有 `Nullsoft` 3 处 / `NSIS` 1 处 → 卸载器也是 NSIS 生成。

注册表（`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\通达信量化看板`）：

```text
DisplayName      = 通达信量化看板
DisplayVersion   = 0.2.0
InstallLocation  = D:\通达信量化看板
UninstallString  = "D:\通达信量化看板\uninstall.exe"
Publisher        = (空)
```

> 注意：`setup.exe` 的 PE 版本资源全空（`CompanyName/ProductName/FileVersion` 均为空），但 `uninstall.exe` 写入了完整卸载键。这是 NSIS 的常见组合——安装器本身不带版本资源，靠脚本 `VIProductVersion` 可选填写。

### 1.5 运行时形态：桌面 WebView 壳（不是"浏览器 + 后台服务"）

从源码字符串可直接读出设计（`app/desktop.py` 一带）：

```text
"桌面客户端入口 — uvicorn 后台服务 + pywebview 桌面窗口"
"1. 单实例锁 — 已运行则聚焦已有窗口并退出"
"2. 选可用端口 — 从 settings.port 起, 被占则递增"
"3. 后台线程起 uvicorn ..."
"pywebview 在 Windows 上经 pythonnet 加载 WinForms + WebView2，后端又用 ctypes 加载了通达信原生 DLL。
 窗口关闭后 uvicorn 已优雅停机 ... 但 os._exit(0) / 普通 return 仍可能卡在模块卸载阶段"
```

- 依赖 `pywebview`（131 次）、`pythonnet`（19 次）、`clr_loader`（137 次）→ Windows 上走 **WinForms + WebView2**。
- 启动器**自带单实例锁 + 端口自动递增 + 强杀退出兜底**（`TerminateProcess` 失败回退 `os._exit`）。
- 主程序清单是 **`asInvoker`**（运行期不需要管理员），只有**安装**需要管理员。
- 安装根**没有** `data/`、`config.json`、`preferences.json` → 这些是**首次运行才创建**。

### 1.6 与通达信的关系：不读注册表，靠目录扫描 + 新 TQ 接口

**路径解析优先级**（源码字符串原文）：

```text
"现在它是可持久化偏好 (preferences.json 的 tdx_home), 可在引导页与设置页直接配置。"
"路径优先级: 用户配置 > 环境变量 > 默认值。"
默认值: D:\new_tdx64
```

**候选目录扫描**（`_candidate_dirs` / `detect_candidates`）：

```text
候选目录名: new_tdx64, new_tdx, new_tdx_test, new_tdx32, TdxW, Tdx, zd_zsone,
            通达信, 通达信金融终端, 新建文件夹 ...
扫描父目录: C:\, D:\, ...、Program Files、Program Files (x86)、Programs、
            software、Software、Apps、Tools、股票、工具
```

- **不查注册表**：`App Paths` 命中 0，`Software\Microsoft\Windows\CurrentVersion\Uninstall` 命中 0；`winreg` 只用于读 Windows Edition / 时区这类系统信息。
- **34 位/64 位问题**：本包是 **x64**，加载的是 64 位通达信客户端的 `TPythClient.dll`。字符串里对 32/64 位不匹配有专门提示。

**DLL 与导出**（`app/datasource/client.py` 一带）：

```text
路径: {TDX_HOME}\PYPlugins\TPythClient.dll     （ctypes 加载）
导出: InitConnect / GetTdxDataStr / CloseConnect
校验: has_dll / has_client_dir / supports_tq_rpc（解析导出表）
```

错误文案（说明"适配"的具体落点）：

```text
"tqcenter 加载失败: 找不到 PYPlugins/TPythClient.dll, 通达信目录可能填错。"
"tqcenter 加载失败: 客户端 TPythClient.dll 缺少 <...> 导出, 这是老接口版本,
 不支持 TQ 通用接口。请换用 2026-09 之后的通达信客户端。"
"tqcenter 加载失败: TPythClient.dll 无法加载(缺少依赖库或 32/64 位不匹配)。"
"已检测到 TPythClient.dll (导出表无法解析, 无法确认 TQ 接口)"
```

**结论（任务一第 6 问）**：「通达信最新版本适配」= 放弃旧的 32 位/旧导出接口，改为 **64 位客户端 + `PYPlugins\TPythClient.dll` 的 TQ 通用接口（`GetTdxDataStr`）**，并在加载前**探测导出表**（区分「DLL 不存在」「DLL 在但导出缺失」「32/64 位不匹配」三种失败），同时把「老客户端」显式判定为不支持。插件声明 `runtime: none`，即**不随包分发通达信 DLL**，全部从用户机器上的 TDX 目录加载。

### 1.8 依赖策略：按需下载（这次最值得抄的一点）

安装包只有 **43 MB**，但安装后目录 ~280 MB。差额来自「**运行时按需补齐重组件**」：

`runtime_deps.json`（schema 1）结构：

```json
{ "schema": 1,
  "packages": [
    { "name": "duckdb", "version": "1.5.3", "filename": "duckdb-...cp314-win_amd64.whl",
      "sha256": "...", "urls": ["阿里云镜像", "清华镜像", "PyPI"],
      "files": [{ "path": "_duckdb.pyd", "source": "_duckdb.cp314-win_amd64.pyd", "size": 37270016 }] },
    { "name": "pyarrow", ... "files": [arrow.dll / arrow_acero.dll / arrow_compute.dll ...] }
  ] }
```

配套还有 `polars_runtime.json`（`polars-runtime-32 1.44.2`，`_polars_runtime_32` 目录），启动时 `app.runtime_deps.ensure_deps()` / `app.polars_runtime.ensure_runtime()` 检查并补齐，带 sha256 校验与多镜像回退。

- 效果：**安装包体积从 ~280 MB 降到 43 MB**（LZMA + 剔除可后补的大轮子）。
- 代价：首次启动可能需要联网下载；离线机器需要预置。

### 1.9 授权与代码保护：**没有**

| 检索项 | 命中 | 说明 |
|---|---|---|
| `机器码` / `激活` / `授权` / `许可证` / `到期` / `注册码` / `序列号` | **0 / 0 / 0 / 0 / 0 / 0 / 0** | 无任何授权文案 |
| `PyArmor` / `pyarmor` | **0** | 无混淆 |
| `Nuitka` | 44 | 编译痕迹（唯一保护） |
| `license` / `License` | 37 / 27 | 上下文全是第三方库（numpy/packaging/apscheduler）的 LICENSE 文本，非商业授权 |
| `activation` | 116 | 全是 `server_activate` / `bind_and_activate`（socket 语义） |
| 联网校验域名 | 只有 `gitee.com/quantdx/tdx-quant-panel`（版本检查）、用户自填的飞书/企业微信 webhook | 无授权服务器、无遥测 |
| 数字签名 | 安装器、主程序、卸载器 **全部 NotSigned** | SmartScreen 必然拦截 |

**结论**：对方的"保护"只有一层——**Nuitka 把 Python 编译成 C 再编译成机器码**，配合「核心引擎编译、插件/策略明文外置」。没有机器码、没有许可证、没有到期、没有在线校验、没有代码混淆、没有加壳、没有签名。

**而这次核查本身就是对其保护强度的实测**：用 PowerShell 读二进制 + 字符串检索，20 分钟内拿到了它的默认通达信路径、候选目录名单、DLL 导出名、错误文案、数据目录迁移逻辑、更新检查 URL、以及全部内部设计注释。**Nuitka 提高的是"门槛"（从改个 py 文件变成要读汇编），不是"防得住"。**

**推荐：方案 C（现状）做主体 + F 的"外置化" + 安装器化。理由（都对应本项目的硬约束）：**

1. **两套 Python 版本**：桥脚本要在 QMT 的 3.6.8 里跑、掘金桥要在掘金终端进程里跑。任何"把桥打进 exe"的方案都是错的。所以主程序 exe 只承载 Core，`live/bridge/` 永远作为**明文旁挂脚本目录**分发（这也意味着桥代码不可能被保护，见 2.6）。
2. **通达信 TQ 同进程 ctypes**：需要真实进程、真实文件系统、真实 `%TDX_HOME%`。onefile 的临时目录会破坏"路径可预期"这一前提（我们的 `config.py` 已按 `argv[0].parent` 锚定，onefile 下虽然仍能工作，但任何 `_MEIPASS` 相对资源都会变成坑）。
3. **UI 自动化三件套**（`pywinauto` / `winrt` / `ddddocr`）：这些包的隐藏导入、COM/WinRT 注册、ONNX 运行时最容易在"单文件自解压"里出问题；standalone 的明文目录便于现场排障（这点对实盘工具很关键）。
4. **升级与数据**：`data/dev.db`、`logs/`、`abi` 迁移脚本必须在 exe 旁边且**不随升级被覆盖**；standalone 目录天然支持"只换程序文件、保留 data"。
5. **编译代价可接受**：现有脚本已跑通，`--disable-cache=all`、`--update-check=never`、`--nofollow-import-to=*.tests` 等坑已沉淀。

**不建议**：E（嵌入解释器 + 源码）虽然升级最爽、杀软最友好，但你的客户机器上"源码可读"意味着**授权等于没有**，且 `winrt`/`pywinauto` 在裸 embeddable 环境下的安装成本高于收益。除非下一步要做「源码级热修」，否则不用。

**安装器**：建议补一层安装器（当前只有 `启动.bat`）：

- 需要"开始菜单/桌面快捷方式 + 卸载项 + 版本号显示" → **NSIS 3.x** 或 **Inno Setup 6** 都可以；
- 与对方相反的选择方向：**装到 `%LOCALAPPDATA%`（当前用户）而不是 `Program Files`**。原因：本平台 `data/` 与 `logs/` 写在 exe 旁边，装到 `Program Files` 会因 UAC 虚拟化/UAC 提权导致 SQLite 写入异常（这也是对方把 data 放安装目录、又必须 `requireAdministrator` 装到 D 盘根的原因）。装到用户目录 = **安装器不需要管理员**，同时也避免了"装完不能写数据"的经典缺陷。
- 卸载器**必须豁免** `data/`（对方注释里明确写了这条，值得抄）。

### 2.3 授权与时限：层级对比（从弱到强）

| 层级 | 做法 | 实现成本 | 用户体验 | 被绕过难度 | 适合的目标 |
|---|---|---|---|---|---|
| **L0** | `config.yaml` 里一个 `licensed: true` 开关；或"序列号 = 固定字符串/校验位" | 1 小时 | 无感（激活是一次性） | **等于没有**：改一行 yaml 即可 | 只做"心理门槛" |
| **L1** | **机器码 + 离线签名许可证文件**（Ed25519 非对称签名；许可证含 `machine_id / exp / features / issued_at / key_id`） | 1~2 天 | 好：复制机器码 → 收 `.lic` → 拖进程序 | 中高：要绕过必须改二进制或 hook 校验点；**换机/重装需重新签发** | **本项目推荐**：防随手拷贝、防离职带走 |
| **L2** | L1 + **在线激活/心跳**（自建轻量激活服务：首次激活绑定机器码、周期心跳、吊销名单、离线宽限 7~30 天） | 4~7 天（含服务端、域名、TLS、兜底） | 中：需要联网；断网要有宽限，否则实盘场景不可接受 | 高：但你自己要承担服务可用性；客户内网/无外网时是负担 | 按年订阅、需要"停用某台机器" |
| **L3** | **代码保护**：PyArmor 混淆 / Nuitka 编译（已有）/ 关键校验下沉 C 扩展或独立授权进程 | Nuitka 已有；PyArmor +1 天；C 扩展 +3~5 天 | 无感 | 高（但都不是绝对） | 防"稍微懂点 Python 的人" |
| **L4** | **运行时防回拨**：持久化 `max_seen_ts` + 单调运行计数 + 与许可证 `issued_at` 交叉校验；时钟回拨判定为"疑似篡改" | 0.5 天 | 偶尔误伤（用户改系统时间/CMOS 掉电） | 高 | 配合 L1 的到期控制 |

**性价比结论**：**L1 + L4**（机器码离线许可证 + 防回拨），再加现有 Nuitka（L3 的编译部分）。L2 只在"你要按年收费、并且真的会去吊销"时才上；L0 不要做——它给你虚假的安全感，还会让后续升级变成"改开关"。

### 2.4 落到本平台：校验点、文件位置、解耦、降级

#### 2.4.1 校验点（三处，缺一不可）

| 层 | 位置 | 行为 |
|---|---|---|
| **启动** | `core/main.py` 的 `lifespan()` 里，`setup_logging()` / `init_db()` 之后 | 读取并验签许可证 → 计算/比对机器码 → 校验到期 → 结果写入进程内单例（`LicenceState`），并落一条 `INFO` 日志。**校验失败不抛异常**（要让 `/api/system/licence` 能返回原因），由中间件与前端提示 |
| **写操作** | 一个 **ASGI 中间件**（不是逐路由加依赖，避免遗漏） | 规则：`path` 以 `/api/` 开头 **且** `method not in (GET, HEAD, OPTIONS)` **且** `path` 不在白名单（`/api/system/licence*`）→ 未授权/已过期则返回 `403 {"code":403,"message":"许可证未激活或已过期，当前为只读模式"}`。这一层同时覆盖 `POST /api/live/sessions/{id}/start`（**实盘下单入口必须 fail-closed**） |
| **前端** | `web/` 启动时 `GET /api/system/licence` | 顶部横幅提示"只读模式/剩余 N 天"；所有写按钮置灰 + tooltip。**前端只是提示，不是防线**（对方这类"纯前端"开关一改就破） |

> SSE 与回测：`/api/live/sessions/{id}/stream` 是 GET，只读放行；正在跑的回测/实盘**不因过期被打断**（见降级策略）。

#### 2.4.2 许可证文件放哪

```
<exe目录>/data/licence/license.lic        ← 推荐（随 data/ 一起备份、升级不覆盖、不进 git）
<exe目录>/data/licence/state.json         ← 防回拨状态（max_seen_ts / run_count / hmac）
```

- **不要放 `config.yaml`**：`config.yaml` 是用户可自由编辑的运行配置（TDX 路径、通道开关），把授权混进去会导致"改配置=改授权"的语义混淆，且现有 `save_config()` 会整文件重写，容易互相覆盖。
- **不要放 `dev.db`**：数据库会随备份/迁移流转，且用户可随意复制；授权状态应是"文件 + 签名"，不是"一行记录"。
- 文件格式（JSON 便于人工排查，签名覆盖 payload 原文）：

```json
{
  "payload": {"v":1,"key_id":"k2026a","machine_id":"<sha256(机器指纹)>","customer":"创懿私募基金",
               "issued_at":"2026-11-07T00:00:00+08:00","exp":"2027-11-07T23:59:59+08:00",
               "features":["live","backtest","ths"],"max_sessions":3},
  "sig": "<base64(Ed25519(payload_json_canonical))>"
}
```

- **规范序列化**（`json.dumps(payload, sort_keys=True, separators=(',',':'), ensure_ascii=False)`）必须在签发端与校验端完全一致，否则"改一个空格就验签失败"。

#### 2.4.3 机器码

建议 3 项稳定量加权哈希（任一项变化不应直接失效，用"至少 2/3 命中"策略）：

| 项 | 取法 | 稳定性 |
|---|---|---|
| Windows `MachineGuid` | `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`（`winreg`，无需管理员读） | 高（重装系统会变） |
| 系统盘卷序列号 | `GetVolumeInformationW`（`ctypes` 调 kernel32） | 中（格式化会变） |
| 主板/BIOS UUID | `wmic csproduct get uuid` 或 WMI（可用 `win32com`/`pythonnet`，但**别为此新增依赖**；可跳过） | 高（换主板会变） |

最终 `machine_id = sha256("v1|" + MachineGuid + "|" + volume_serial)[:32]`。**不要**用 MAC 地址（虚拟网卡/随机 MAC 太多）。**不要**用 CPU 序列号（Hyper-V/云主机常为空）。

#### 2.4.4 未授权 / 到期后的降级行为（关键决策）

| 状态 | 启动 | 读接口 | 写接口 | 实盘 |
|---|---|---|---|---|
| 已授权（有效期内） | 正常 | 放行 | 放行 | 正常 |
| **宽限期**（到期后 N=7 天） | 正常 + 显著告警 | 放行 | **放行**（但每次写操作日志 WARNING，前端横幅红字） | 允许**存量**继续运行/平仓，**禁止新开仓/新会话** |
| **过期**（宽限结束） | 正常启动但**只读模式** | 放行 | 403 | **禁止 start**；已运行的会话允许 stop/平仓类操作（避免持仓无法处置） |
| **未激活 / 机器码不匹配 / 验签失败** | 正常启动但**只读模式** | 放行 | 403（含 `/api/live/*/start`） | 禁止 start |
| **系统时间回拨疑似篡改** | 正常启动 + 醒目告警 | 放行 | 403 | 禁止 start |

**为什么不是"拒绝启动"**：本平台是**实盘交易系统**。硬拒绝启动会让用户在自己持仓浮亏时既看不到数据也无法平仓——这在商业上比"被破解"更伤。所以：**读永远放行，写按状态 fail-closed，实盘开仓是唯一必须硬拦的动作**。

**为什么不在运行中砍会话**：到期瞬间强杀会造成"持仓无人管"。正确做法是**到期后只禁止新动作**（新开仓/新会话/新回测），已运行的会话保留 `stop/平仓/撤单` 这类"降低风险"的操作。

#### 2.4.5 私钥与签发工具

- **私钥绝不进仓库、绝不进 exe、绝不进 CI 制品**。放离线机器或 U 盘（加密压缩 + 口令），文件权限仅本人。
- 签发工具建议单独一个小脚本（**不进 `main/` 包，避免被 Nuitka include**），例如 `tools/licence_issue.py`（本轮不实现）：
  - `python licence_issue.py --machine <用户发来的 machine_id> --days 365 --features live,backtest --out alice.lic`
  - 私钥读取走环境变量或本地路径，公钥硬编码/内嵌在 `core/licensing.py`。
- **公钥内嵌**是必要的（离线验签必须用到），这不是秘密；**Ed25519 的价值就在于"公钥公开也伪造不了签名"**。
- 密钥轮换：许可证里带 `key_id`，程序内保留 `{key_id: public_key}` 小字典（2~3 把），便于旧证换新钥而不用让所有客户立刻升级。

#### 2.4.6 Ed25519 验签怎么落地（不新增依赖的两个选项）

Python 3.13 标准库**没有** Ed25519。二选一：

1. **引入 `cryptography`**（推荐，成熟、纯二进制 wheel，Nuitka 打包正常）：`from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey`。实现量 10 行。
2. **内嵌"只验签"的纯 Python Ed25519**（RFC 8032，约 120~180 行，只实现 `verify`，不实现 `sign`）：零新依赖，但需自己写测试向量（RFC 8032 §7.1 测试向量可做单测）。
3. 兜底但**不推荐**：HMAC-SHA256 对称签名（标准库 `hmac`）——密钥必须随程序分发，等于"改两行就能伪造"，只能防"完全不懂的人"。

> 本轮约束是"不新增依赖"，所以这里只给结论：**实现阶段优先选 1**（`cryptography` 已在多数环境存在，且 Nuitka 对其有现成支持），若坚持零依赖则选 2，并把 RFC 8032 测试向量写进单测。

#### 2.4.7 防回拨（L4）

```
state.json = { "max_seen_ts": <unix>, "run_count": n, "hmac": hmac_sha256(k, payload) }
k = sha256(license.sig)[:32]      # 由许可证签名派生，改 state 文件无法凭空构造合法 hmac
```

判定逻辑：

1. `now < license.issued_at - 1天` → 系统时间早于签发时间 → **可疑**；
2. `now + 1小时 < state.max_seen_ts` → 时间被回拨 → **可疑**；
3. 每次启动写 `max_seen_ts = max(old, now)`、`run_count += 1`；
4. 判定"可疑"后：只读 + 告警，**不销毁许可证**（用户 CMOS 掉电/时区错乱是真实存在的，误杀成本高）；
5. 到期判断用 `min(now, max_seen_ts)` 做上界，避免"把时间调回 2026 年继续用"。

| **P0（现状）** | Nuitka standalone + `启动.bat` | 已有 | 无授权，适合自用/内部 |
| **P1** | `core/licensing.py`（验签+机器码+到期+防回拨）+ `/api/system/licence` + 写操作中间件 + 前端横幅 + `tools/licence_issue.py` | 1~2 天 | 覆盖"防拷贝 + 到期停用"80% 的需求 |
| **P2** | 安装器（NSIS/Inno，装 `%LOCALAPPDATA%`，卸载豁免 `data/`）+ 版本资源 + 图标 | 0.5~1 天 | 替代 `启动.bat`，给客户"像个软件"的体验 |
| **P3（可选）** | 代码签名证书（OV/EV） | 采购周期 | 直接消除 SmartScreen 拦截；否则必须教用户"更多信息 → 仍要运行" |
| **P4（可选）** | 在线激活/心跳 + 吊销 | 4~7 天 | 只在订阅制/需要停用某机器时做 |

**P1 与现有代码的兼容点（实现时注意）**：

- `lifespan()` 里已有一串"启动恢复"（僵尸回测/实盘置 stopped、watchdog），**授权校验必须插在 `init_db()` 之后**，不要打乱这些恢复逻辑的顺序。
- 中间件要**排除** `/api/system/licence`、`/health`、`/debug-path`（诊断用）；SSE 是 GET，天然放行。
- `_is_frozen()` / `is_frozen_app()` 已有"exe 目录锚定"能力，许可证路径直接复用同一套锚定逻辑即可，**不要**再写一份 `sys.frozen` 判断（Nuitka 下它是 False，这是本项目已踩过的坑）。
- 配置与授权解耦：**不要在 `config.yaml` 加 `licensed` 键**，也不要让 `save_config()` 能碰到许可证文件。

### 2.6 风险与边界（必须写清楚的部分）

**1）纯 Python 本地程序不可能做到绝对防破解。**
我们这次对 Nuitka 包的实测就是证明：没有 PyArmor、没有加壳的 Nuitka 程序，其**全部字符串（含中文注释、默认路径、DLL 导出名、错误文案）都能被 `strings` 级手段读出来**。加密字符串、控制流混淆、校验下沉 C 都只是把破解从"20 分钟"推到"几天"。

**2）先定义"防谁"，再决定投入。**

| 目标对手 | 建议投入 | 说明 |
|---|---|---|
| 防"随手拷给朋友/同事" | **L1 机器码**（1~2 天） | 拷贝过去机器码不符，直接只读；这是 90% 的泄露场景 |
| 防"离职人员带走整套" | **L1 + 到期 + 按客户签发** | 加"每客户一份证、到期停用"就够；不必上在线激活 |
| 防"专业逆向/二次分发破解版" | L2 + L3 + C 扩展（数周） | **投入产出比很差**，除非产品单价很高；且永远做不到 100% |
| 只是"心理门槛" | 先别做 | L0 会让团队产生虚假安全感，还增加维护面 |

**3）代码保护的隐性代价（很实际）：**

- **杀软误报**：Nuitka/PyInstaller onefile + 未签名 → Defender/SmartScreen/360 大概率拦。本项目还额外碰 `pywinauto`（键鼠注入）、`winrt`（OCR）、`ddddocr`（ONNX）——**这些行为本身就像外挂**，误报概率高于普通应用。缓解手段只有：代码签名证书 + 少用 onefile + 提供哈希/官网校验。
- **维护成本**：Nuitka 编译 10~30 分钟/次；`winrt`/`pywinauto`/`ddddocr` 的隐藏导入每次升级都要回归；PyArmor 额外引入"混淆后 traceback 不可读"的排障困难，以及商业授权费用。
- **桥脚本无法保护**：`live/bridge/*.py` 必须在 QMT 的 Python 3.6.8 / 掘金终端里明文运行，**这部分代码任何方案都保护不了**。可接受的理由是：桥只是"哑执行器"，真正的策略逻辑、参数、风控在 Core；且桥的 HTTP 端点本来就有 token/本机回环限制。**不要把商业机密放在桥里。**
- **`tqcenter` 不是我们的**：通达信 DLL 只能从用户机器加载，这决定了"必须本机装通达信客户端"，也决定了无法做"云端托管"式授权。

**4）许可与合规**：许可证里建议写明"授权范围（机器数/账户数）"，到期后只读而非销毁数据；避免出现"到期后用户无法导出自己的回测结果"这类纠纷。

### 2.7 对方实现：哪些值得抄、哪些不要学

**值得抄：**

| 做法 | 为什么 |
|---|---|
| **Nuitka standalone（非 onefile）** | 启动快、路径可预期、ctypes/COM/OCR 类依赖最稳；本项目现状已是这条路 |
| **核心编译 + 插件/策略明文外置**（`app/strategy/builtin/*.py`） | 既保护引擎，又给用户"自己写策略"的扩展性——与我们的"公式/策略可配置"取向一致 |
| **`data/` 放安装目录旁边 + 卸载豁免** | 升级不丢数据；本项目 `build_package.py` 已保留旧 `data/`，思路相同 |
| **依赖按需下载 + sha256 + 多镜像** | 43MB 包 vs 280MB 安装；本项目 `polars`/`pyarrow`/`onnx` 都是大件，若安装包体积重要，可借鉴"基础包 + 可选组件" |
| **失败文案分档**（DLL 不存在 / 导出缺失 / 32-64 位不匹配） | 实盘工具的用户支持成本极高，这类可执行的中文错误提示直接省人力；我们 TQ/THS 通道也应保持这个标准 |
| **SPA fallback**（未知前端路由回 index，`/api` 仍 JSON 404） | 本项目 `SPAStaticFiles` 已实现，保持一致 |
| **更新检查"离线静默失败 + 结果缓存"** | 不阻塞启动、不刷屏；适合内网/离线客户 |

**不要学：**

| 做法 | 问题 |
|---|---|
| **完全没有授权** | 一个 exe 拷走就能用；离职/转手零成本 |
| **不做数字签名** | 安装器 + 主程序 + 卸载器全 NotSigned → SmartScreen 必拦，客户第一印象是"这是病毒" |
| **安装器 `requireAdministrator` 且装到可写盘根目录** | 因为 `data/` 写在 exe 旁，只能用管理员装到非受保护路径；正确做法是装 `%LOCALAPPDATA%`，安装器不需要提权 |
| **`.iss` 注释残留 vs 实际 NSIS** | 打包脚本与发布物不一致，会误导后来人；我们应保持 `build_package.py` 与发布流程单一来源 |
| **前端依赖外网 CDN 字体**（rsms.me / Google Fonts） | 内网/离线环境首屏字体缺失；本项目应坚持本地字体资源 |
| **源码注释里直接写内部设计细节**（默认路径、迁移策略、强杀逻辑） | 本次核查正是靠这些注释快速还原了它的架构；**我们自己的注释也要注意不要在分发物里暴露敏感设计**（Nuitka 不会删注释字符串） |

### 2.8 需要你拍板的点

1. **防护目标**：只防"拷贝给朋友/离职带走"（→ L1 足够），还是要防"专业逆向/做破解版"（→ 需要 L2+L3+C 扩展，投入数周且仍不绝对）？
2. **是否需要在线激活/吊销**：如果要"按年收费 + 能远程停用某台机器"，就得接受"服务端 + 域名 + 离线宽限"的复杂度；否则纯离线许可证更省事、也更适合无外网的实盘机器。
3. **是否愿意接受杀软误报**：若愿意买代码签名证书（OV/EV），误报与 SmartScreen 一次解决；若不买，就必须接受"首次运行需手动放行"，并在分发说明里写清楚。
4. **到期后的行为**：建议「7 天宽限 → 只读 → 实盘禁止开新仓」，是否接受？还是希望"到期直接拒绝启动"（更硬，但用户持仓风险更高）？
5. **安装形态**：继续用 `启动.bat`（零成本），还是做安装器（体验更好、需要维护安装脚本与升级兼容）？
